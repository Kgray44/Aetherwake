# Inline conversation draft integration

The inline block now mounts Conversation Product's released `mountConversationChat` through `mountBlockChat`; the full manager uses that same component. Normal usable and focused poses share the exact transcript/composer nodes, resource ID, external `ConversationDraftSession` and native execution adapter. Hidden/tiny views release execution observation without replacing their editor. The application retains its resource-owned sessions for the native-window lifetime, including sends that outlive a closed view. Closing/draining persists drafts independently of a pending provider RPC.

Every Send checkpoints its exact edit generation through the same public ConversationProductPort and trusted native broker as the full manager. Canonical submission evidence must match before that checkpoint is acknowledged. Provider completion, user task completion and verified outcomes stay separate. Later typing, native cancellation, revision conflicts, failed or unconfirmed submissions retain recovery without automatic replay. Explicit conflict decisions bind the displayed stored revision. One canonical schema2 API and coordinator own persistence; no parallel transcript, draft store or provider path is introduced.

Earlier API/session integrations (57347c8/a608938), schema2/native admission b18da0e and owner delayed-read correction a43da751 remain historical dependencies. Shared chat and deferred-send ownership corrections are adopted in c369028/787d221/43b82e2. The identity release recorded48 Conversation Product tests, including actual SQLite recovery, alongside source/component tests; those are not native inline interaction proof.

For a parent-assigned native slot, use `--integration-direct --verify-inline-drafts --verification-deadline-ms=<1000..90000> --profile=<new private profile>`. The host installs its hard close deadline before opening its one test window and forwards the original `moduleStarted` through the actual direct-verification route. The helper requires that timestamp and explicit deadline. It never shows, resizes, or reclaims focus itself. Each input event, text insertion, capture and awaited continuation validates the same live owner/deadline. Lost focus, hidden/minimized/destroyed contents or timeout stop subsequent actions. CPU guard/route tests use window stubs only.

The helper creates a canonical local chat through Library input, types through native input, injects an explicitly synthetic competing composer through the admitted API, resolves conflict through the shared component controls, switches workspaces, tests graphics loss/recovery and corner resizing, then saves the exact unsent checkpoint and exits. Repeat with the same profile plus `--verify-restore`; the fresh process must restore the exact text/version and no message, then one native local Send must record exactly that user message and clear only its acknowledged draft revision. The helper retains the full original checks; the safety correction does not replace them with a smaller acceptance definition.

Output bounds are two PNGs totaling at most8MiB, a512KiB receipt, a128KiB checkpoint and20 bounded console errors. Existing checkpoint/capture files are never overwritten. Captures require foreground ownership and a fresh positive draw submission; callback/draw timing is not displayed FPS. The host's deadline remains the final close authority, while a bounded failure receipt may be written after focus loss without any further input or capture. No real provider, model inference, private reasoning or verified task completion is exercised. The revised helper remains unrun on the integrated native application.
