# Native Library and named-template journeys A/C

This verifier is source readiness, not a passed native acceptance claim. It is queued after the parent's frozen review C. The Universal worker must not launch a window, Electron, backend daemon or capture. The application integration lead owns that native slot and its build/source/profile identity.

`prepare-library-native.mts` creates schema in a new dedicated private profile. It refuses existing profiles, checks the C:/D: reserve before writing, admits at most 512 MiB on the profile drive (and 16 MiB on C: for source/output when the profile is on D:), and checks the small closed database against a 32 MiB checkpoint and the seed against 64 KiB. It starts no provider transport. It creates **zero ordinary projects, workspaces, resources or placements**. Before allocating the profile it compiles all 36 renderer-expression factories (42 branch/data cases) in both the direct and guarded wait contexts. Selectors, labels and values use JSON encoding. The seed records that preflight digest and the expression module hash, plus eight source hashes including the actual Core and engine. The native helper checks those bindings before its driver starts and compiles every instantiated expression before sending it to Electron. This is preparation, not native interaction or an OS disk quota; it cannot constrain unrelated/unloaded writers.

The existing native host entry `--integration-workspace-views` delegates only when the additional explicit `--verify-library-templates` option is present. The normal ten-kind/three-shape verifier is unchanged for its ordinary invocation. Both invocations require the original host module timestamp and an explicit deadline of at most 90 seconds. The host's original hard deadline still owns termination.

Example owner commands, after building the exact candidate and admitting its full allocation:

```powershell
node prototypes/block-library/prepare-library-native.mts --profile=C:\private\review-workspace-native-ac-new-a
```

From the cinematic application directory:

```powershell
.\node_modules\.bin\electron.cmd native/desktop-main.cjs --integration-workspace-views --verify-library-templates --profile=C:\private\review-workspace-native-ac-new-a --verification-deadline-ms=90000
```

After that actual process exits successfully, launch a **separate process** with the same arguments plus `--verify-restore`. Failed or consumed profiles are evidence; never restart an initial journey against a partly populated profile or replay a completed user action as fresh preparation.

The initial journey uses actual native clicks, keyboard input, native selects, direct card drags/resizing and a native wheel departure. It creates a project and a workspace through the current Blank Template UI, then creates local Chat, Note and Task through the current Block Library. It records one local user message, keeps a separate unsent draft, toggles the real task, edits the Note, removes/re-attaches it twice through actual card context and Attach Existing controls, and checks exact canonical identity/content. It changes Freeform through the compact layout controls, arranges/resizes cards directly and saves a real 125% Note presentation.

It then captures a named template through the actual Template Library, choosing **new empty Chat** plus **same-ID Note and Task references** explicitly. It checks the actual layout preview and binding counts, verifies that text/history/drafts are absent from template metadata, leaves the source workspace with the existing native wheel navigation, finds/previews/instantiates the saved template, and checks new placement IDs with exact captured geometry and configuration. The new Chat must have zero canonical messages and an empty draft. Changing the instance's geometry, independent Chat draft and Note scale to 150% must leave the saved template and original workspace/settings unchanged. Read-only native RPCs validate these effects; they never create/capture/attach/instantiate or change geometry in place of UI actions.

The separate restore run checks both workspace geometries/organization/presence/viewports, full canonical resource identities/content, saved template, independent drafts and exact per-placement settings. It also verifies restored actual Note typography. No model execution is allowed in either run. This is an offline local-recording conversation journey, not Codex inference or conversational Vela acceptance.

Each run preserves one bounded 512 KiB JSON receipt; the initial run writes one exclusive checkpoint of at most 128 KiB. At most two PNGs, totaling at most 8 MiB, are allowed. Initial screenshots show the actual Chat Library details and actual named-template preview. A failure uses only a remaining screenshot allowance. A diagnostic PNG may retain observed script/window errors when the renderer and GPU remain healthy; it records that health and cannot make the failed receipt pass. Passing PNGs still require zero observed errors. Both paths require a new draw and the same focus/deadline/byte limits; after both slots are used its receipt/phase/last native intent and guarded state diagnostics remain the evidence. Focus loss, minimized/hidden/destroyed window, the same deadline or operator Escape stops the run. Automation sends no Escape and never reclaims focus. A cancellation cannot retroactively undo an already started canonical transaction. Listeners are released and only the owned app is exited.

CPU guard tests and an actual schema-only Core/SQLite reopen test establish preparation, deadline/cancellation and dispatch behavior. They do not execute this UI journey. Missing controls, stale data, unavailable capabilities, occlusion or timing failures must remain failures with evidence; do not skip a step or replace user input with a backend write. Actual owner-run initial/restart receipts, visual review and appropriate performance evidence remain required.
