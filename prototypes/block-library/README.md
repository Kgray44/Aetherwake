# Block and Workspace Template Libraries

Functional modules for the existing native Aerynth application, using injected canonical services and the shared renderer. Runtime views and services own no database connection, transcript store or provider executor. The explicitly synthetic diagnostic scripts use the existing Core to prepare separate private test profiles.

## Integration

`contracts.ts`, `registry.ts`, `model.ts` and `view.ts` are browser safe. Import `style.css` once. Mount `mountBlockLibrary(root, port, options)` from the existing Add action, or `mountWorkspaceTemplates(root, port, options)` from New Workspace. Dispose the mount on close. Both use the injected native ports; creation opens the parent's canonical block controls through `onCreated` / `onApplied`.

The block mount requires `workspaceId`, `expectedLayoutVersion` (a getter is supported), `onCreated`, and `onClose`. The template mount requires `projectId`, its `expectedProjectVersion` when non-null, `onApplied`, and `onClose`. Supply `currentWorkspace: () => DesktopSnapshot | null` to expose Save Current Workspace. Its binding controls require an explicit **reuse existing resource** or **create empty new resource** choice for every resource.

On the native side, instantiate `new TemplateService(canonicalDb, host, optionalVelaPlanner)`. `CanonicalTemplateHost<DatabaseSync>` is the exact adapter contract. `host.db === canonicalDb` is enforced. `host.atomic` must encompass the same kernel transaction and rollback any canonical in-memory state (the integrated backend's existing `atomic` wrapper provides this). All host methods are synchronous. No host call may launch provider work while applying a template.

The host creates resources without placements, then creates placements independently. Stage a new workspace in Freeform while placing all roles. `setOrganization` runs once after placement creation, with role order and spans already remapped to canonical placement IDs; the workspace engine owns final Fluid/Structured resolution. Use its normal geometry/version validation. Vela stays the separate existing 208 × 260, scale .65 presence; it is never encoded as a template resource or padded placement.

For individual Library create/attach commands, omitting both `presentation.x` and `presentation.y` requests vacant initial placement through the canonical engine's existing nearest-candidate solver. It keeps every existing Freeform placement and Vela exact, including intentional overlaps between existing cards. Either explicit coordinate preserves the caller's position; template/capture/restore geometry keeps its existing path. The trusted host advertises `initialPlacement: 'nearest-free'`; a legacy host without it refuses automatic placement before creating a resource. All three mutation inputs accept optional workspace-engine `Geometry` bounds as transient placement context, included in their atomic retry fingerprint. Supply `mountBlockLibrary`'s optional `bounds()` callback from fresh usable world bounds for its exact workspace; a normal browser Attach supplies the same field directly. Prefer a free candidate inside supplied bounds; if none fits, preserve dimensions in pannable overflow and use the existing reveal behavior. Bounds grant no access or authority.

For distant or small saved cards, `mountBlockIdentity` accepts an optional `approach({minimumBodyWidth, minimumBodyHeight})` camera action and returns `setFootprint(context): 'working' | 'overview'`. `BlockFootprint` in `presentation-policy.ts` contains projected CSS-pixel `width`, `height`, `bodyWidth`, `bodyHeight` and positive configured `textScale`. Feed actual retained body content dimensions from the host's shared measurement cache and its existing projection; no per-card observer or frame loop is installed here. Overview overlays that same body wrapper, preserves full child layout/DOM/controller/draft identity, and temporarily hides/inerts those children. Its type-specific summary uses the existing canonical identity model. The header offers Approach and an explicit Open fallback; the host owns camera movement, exact Return and keyboard focus after approach. Open retains its existing handler and accessible name, and a refused camera approach never silently expands the resource. Per-kind readability values and hysteresis are engineering calibration, require native visual qualification, and never change canonical geometry or permission/activity. Working input focus and IME composition pin working mode; header/Approach focus does not. Unknown initial measurements and absent camera integration retain the existing working composition. Unavailable views keep their existing recovery lifecycle.

Call `setFootprint` only after the shared body observer has an actual entry; do not synthesize zero for an absent cache. Zero measured body space with positive projected card dimensions is a real exhausted layout and selects overview, keeping header Approach reachable. Hidden projected cards or invalid/missing dimensions retain their prior composition.

Feed the existing canonical placement flag through `identity.setMinimized(boolean)`. `identity.minimizedPresentation()` returns the exported readonly `BlockMinimizedPresentation`: `canonicalMinimized`, `effectiveMinimized`, and nullable `deferredReason` (`composition`, `uninitialized`, `loading`, or `unavailable`). The optional `onMinimizedPresentationChange(state)` action is the single transition notification for the host's existing Motion Coordinator: physical shrink follows **effectiveMinimized**, preserving stored dimensions, camera and independent Vela presence. Repeated projection/footprint updates do not wake it again. IME defers effective collapse through compositionend and its settling microtask; a new composition, canceled request or disposal fences queued work. Unavailable/loading views keep their recovery controls. This observation owns no persistence or geometry.

Supply `restore(): Promise<void>` to the same identity mount for its explicit Restore header action. It requests the canonical desktop `setBlockMinimized` action with the current workspace/block versions and layout revision. The view waits for the canonical flag to update; it never clears it optimistically. Failed changes retain the summary/data and expose an error, and absent integration leaves Restore disabled. The desktop adapter rejects departed/foreign workspace context and the engine retains its active-subject/lock/version fences, persistent command receipts and existing undo/checkpoint/restart behavior. An unchanged flag changes neither layout nor desktop session/event revision. Root's App/coordinator/Inspector wiring passes the actual Chat/Note/circle-Reference initial and restart journey at `5b2af123`, including the 35% Restore hit and exact draft recovery. Real native IME and the wider kind/constraint matrix remain open; see [the acceptance audit](ACCEPTANCE-AUDIT.md).

Bridge these methods to their matching `WorkspaceTemplatePort` / `BlockLibraryHostPort` promise methods: `capabilities`, `createBlock`, `listTemplates`, `getTemplate`, `saveTemplate`, `renameTemplate`, `archiveTemplate`, `previewTemplate`, `applyTemplate`, `requestVelaTemplate`. Native `readProject`, `readWorkspace` and `readResource` must return effective authorization and current state/version; fail closed rather than inferring access from existence.

`requestVelaTemplate` only invokes the optional real `VelaTemplatePlanner.plan` port. No planner or unavailable Vela capability yields `vela_planning_unavailable`. A returned plan retains request/provider/model attribution and is reviewed, saved and checked before apply. No fallback AI generation, transcript cloning or Codex delegation is hidden in this module.

## Behavior

- Ten manifests include three nonresource subject views (Project Overview, Resource Browser and Collection Browser), with explicit native grants and runtime capability state. Subject views retain tagged canonical references and create no resource rows.
- Seven built-ins map to implemented desktop kinds: Conversation, Note, Research, Task, Task group, Reference and Intelligence Stream. Runtime capability state controls creation. Absent capabilities are unknown, unavailable providers are explicit, and the preview describes real existing controls. Streams display recorded events only.
- Blank defaults to Fluid. Development, Research and Planning create supported canonical chats/notes/tasks/groups with real task membership. Presets are read-only templates; users can save their own layouts.
- Template resources and placement roles have separate keys. Multiple placements may reference one resource role. Reuse preserves the canonical resource ID and ownership. New resources begin empty; note text, messages, credentials, provider bindings and executions are excluded by a strict schema.
- Named templates support versioned save/update, rename, list/search, preview, archive/restore and restart persistence. The extension tables live in the injected canonical SQLite database.
- Apply always creates a new workspace. Counts and JSON bytes are bounded; template/project/reference versions, archive state, access and cross-project restrictions are rechecked inside one transaction. Existing global resources may be referenced; project-owned resources must match the target project. Reused task groups are never modified by template membership.
- Create/apply have persistent operation receipts. Same request ID/input returns its canonical result; changed input conflicts. Failure rolls back all workspace/resource/placement/membership/receipt changes. Metadata capacity is explicit (256 templates, 64 resource roles, 64 placements, 64 KiB body, 4096 receipts, 8192 extension audit events); reaching capacity fails rather than deleting retained records.

Attach Existing includes progressively disclosed project and collection filters. Project choices narrow the existing compatible-resource fence to the workspace's project or to unassigned resources. An authorized collection only narrows that set; it cannot make a foreign-owned resource attachable. Collection grants and archive state are rechecked on every discovery read. Failed scope reads clear stale Attach actions while preserving the form's title, geometry and configuration. Collection metadata loads only when the user opens its filter disclosure. Filter availability is advertised explicitly; older hosts retain ordinary compatible search without inferring support from a method name.

## Workspace identity and direct use

Each registered kind now has its own canonical-data composition: a shared chat transcript/composer, editable document, single task, task checklist, received-event timeline, project counts/workspaces, resource table, collection stack, research findings/sources, or leading reference citation. Type-specific glyphs and restrained accents sit on the existing continuous glass; the renderer material union and creative assets are unchanged. Missing data, partial counts, unavailable resources and unexecuted sources remain explicit.

Usable normal workspace notes and chats expose their real editor immediately. Tiny/receded cards retain concise previews. Both normal/focused chat poses mount the same Conversation Product component, resource-owned draft session and native execution adapter. Pausing releases execution observation without replacing the transcript, composer, cursor or scroll. Draft sessions remain owned for the native-window lifetime so closing a view during an outstanding Send cannot dispose the canonical draft owner. Leaving a chat never waits for provider completion or replays a send.

Open/Back is the existing action in the upper header. Moving uses the card surface, resizing uses its invisible edges/corners, and the workspace retains its compact layout-mode buttons. New blank/template/graph-created workspaces invoke the existing camera-only Bring-all command once after creation; reopening and restoring saved workspaces do not rewrite the camera or card geometry.
