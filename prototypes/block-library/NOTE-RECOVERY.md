# Note recovery port

`NoteExperienceService` retains unsaved note/research/reference/task text on the same canonical SQLite connection. It opens no database and does not replace the canonical note service. `createCanonicalNoteHost` validates the actual kernel connection, reuses the template host's effective resource grants, delegates content writes to the existing DesktopState command, and accepts an optional parent-owned canonical rename callback.

Release these methods through the trusted native boundary: `readNote(resourceId)`, `saveNoteDraft({resourceId,expectedDraftVersion,baseResourceVersion,content})`, `commitNote({resourceId,expectedResourceVersion,expectedDraftVersion,content})`, `discardNoteDraft({resourceId,expectedDraftVersion})`, and `renameNote({resourceId,expectedResourceVersion,title})` when available. DTOs are in `note-contracts.ts`.

The editor should recover `draft.content` when present, show a conflict when its base resource version is stale, and retain that text until the user resolves or discards it. Serialize draft writes using the returned revision, persist recovery text before committing it, and await pending writes before a workspace transition. `commitNote` atomically fences both canonical resource and draft revisions. Failure rolls back canonical content and retains recovery text. It never silently rebases a stale draft or overwrites a newer editor's draft.

`draftRevision` is monotonic even after commit/discard. This prevents an older tab's revision from matching a newly created draft after a clear-and-recreate cycle. Archived/revoked resources deny access without destroying their recovery data. Drafts use the existing 100,000-byte note-content limit, an explicit 8,192-resource retention bound, and a 32 MiB aggregate text bound. Reaching a bound fails without deleting other work.

Four focused actual SQLite/DesktopState tests pass for restart recovery, conflict handling, competing editors, failed canonical commit rollback, monotonic revisions, and revoked/archived content. Strict TypeScript checking passes. Native editor wiring and an actual interrupted-save desktop journey remain integration work; these tests do not claim that unsubmitted keystrokes survive a process kill before the host receives them.


## Desktop editor wiring

`NoteSession` serializes all draft and canonical writes for one resource. The application keeps one session shared by its placements and opens editors. Every edit requests a durable recovery draft immediately; the existing 350 ms save window commits only after the draft response. Text typed during an in-flight commit is retained and committed at the next canonical revision descended from that own write. Canonical and competing-draft conflicts stop automatic overwrites. Explicit **Replace saved version with my text** and **Use saved version** actions refresh fences and preserve newer text typed during a recovery request. A storage failure retains local text and any already persisted draft. Text that never reached the native host still cannot survive process termination.

The native shell uses the existing `notes` RPC envelope through `notes-client.ts`. Opening, resizing, arranging, and canonical snapshot updates retain the textarea node and its existing input listener; selection is changed only for an actual content update or a deliberate Find action. The application awaits session flushes before workspace changes. Actual source editors now support rename, find-next/previous, a safe basic Markdown reader (headings, lists, quotes and code), and explicit recovery inspection. The reading preview is bounded to 1,500 lines; Write retains the complete document within the canonical 100,000-byte limit. Research and Reference reading show up to 50 credential-free HTTP/HTTPS links parsed from the user's document, labeled as user-provided and unverified; they can be copied. External fetching/opening is not claimed by this renderer.

Sessions are created on editor expansion, with no polling. Hidden views skip Markdown/recovery DOM rendering; canonical note state remains synchronized in the shared session. Clean unobserved sessions outside the current workspace are released. Dirty sessions remain retained. The shared compact layout controls, direct surface movement, edge/corner resizing, physical materials, GPU and Motion Coordinator remain in their existing owners.

Nine actual SQLite/service/coordinator notes tests pass, including interruption/restart, competing canonical and draft writers, ABA fencing, rollback/retry, edits while a commit response is delayed, and revocation. Three renderer transport/source-link tests pass. App TypeScript and production Vite build pass. These source checks do not replace native UI proof: native draft interruption/restart, conflict choices, rename/search/reading, multiple placements, workspace transitions, graphics loss and typed subject cards still require the integrated host's acceptance run.


The editor's persistent action row is now two controls: Read/Edit and an accessible Document actions disclosure. Find/previous/next and Rename appear only inside that contextual disclosure. Escape or an outside pointer dismisses it; its listener is removed on disposal and hidden views close it. The existing content field remains the same DOM node. This compacts the native-reported button bank while retaining readable action names and keyboard discovery. Native visual review of the revised row remains required.
