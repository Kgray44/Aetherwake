# Canonical Agent block presentation

`mountAgentBlockExperience(root, canonicalAgentResourceId, options)` renders an existing Agent profile over Root's `AgentLibraryClientPort.inspect/effective` seam. Root injects its actual borrowed `ExperienceMotionPort`, a unique presentation `viewId`, `onOpenAgent(resourceId)` and optional canonical resource navigation. Import `agent-view.css`. The shared host calls `frame()` and `reflow()`; the component owns no scheduler, provider, resource factory, workspace, assignment service or event database. Root retains the independent Agent Library and profile editing.

The working presentation uses a named profile, monogram, authored purpose, specialties, effective configuration and progressive configuration disclosure. Catalog compatibility is explicitly separate from provider entitlement and execution. No Run, Assign, approval, progress or cancellation control is advertised through an unavailable execution seam. Open agent uses Root's actual library/direct route.

The optional existing `references` reader is absent in the released Root client. The block reports history as unavailable until Root supplies a current-authority reader. When provided, it displays the last four returned canonical reference records and the number loaded, never a claimed lifetime total or current assignments. A manual compatibility Task retains that identity. `referenceOnly`, `startsExecution: false` and `taskVerified: false` do not become running activity, a result or verification. Historical profile versions remain attached to their actual references. The block does not derive a history list by reading private tables or start an execution.

Inactive initial views perform no reads; stale asynchronous reads cannot replace newer state. Current-authority denial clears profile/configuration/reference content, including denial after initial inspection. Closing becomes inert immediately and uses Root's shared pose; disposal removes only this presentation's keys. Source tests use the real canonical Agent service/Kernel SQLite with explicit synthetic policy and cached catalog, plus the existing MotionCoordinator and a finite host-driven CPU DOM boundary. The optional test history reader reauthorizes known fixture reference IDs through the existing service; it does not claim a production history-list API. There is no native input, layout, provider, motion-performance or artistic acceptance claim.

Block manifest/type-map promotion and actual workspace mounting remain a Root integration gate. Canonical Agent existence alone does not make an Agent block available. The local Root Agent module and existing shared contract/motion dependencies are excluded from this worker's release; only the owned component, CSS, tests and this integration note are delivered.
