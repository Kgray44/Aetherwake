# Retained canonical Timeline viewer

`mountTimelineExperience(root, canonicalTimelineResourceId, timelinePort, options)` supplies workspace or direct content over Root's existing Timeline service. Options are `{ motion, viewId, active?, presentation?, onOpenResource?, resourceTitle?, onProjection? }`. Import `timeline-view.css`. Root calls `frame()` from its existing loop, `reflow()` after resizing and `refresh()` when the canonical resource/policy changes. The controller also exposes `setActive`, `setPresentation`, `flush` and `dispose`. Each presentation owns only its own borrowed motion keys. There is no coordinator, scheduler, clock engine, event database, provider or resource factory in this component.

The working composition has a capture-position track, source lanes, a bounded event list, local selection/provenance inspection and actual canonical source navigation. Source classifications remain observed/reported/inferred/simulated. Capture time and display time zone are identified; UTC range input never silently uses the machine's local time zone. Event/capture references appear only in the selected provenance inspector. Provider status and captured events do not become verified task completion or global causality. Planning, forecasts, state reconstruction, re-execution and export are not advertised; the service supports Activity and Execution modes only.

Only fresh `TimelineDocument.canEdit === true` enables saved pan/zoom, filters, previous saved view and Save view. It is a current host hint, never a grant; the actual save rechecks backend authority and canonical version. Local event inspection remains usable in a read-only view. Explicit Save view includes the local selection. Unsubmitted settings stay view-local; `flush()` waits for submitted saves and rejects unknown outcomes rather than implicitly submitting a form. Root should retain a hidden controller when it wants to preserve these local drafts.

Each Next events request uses the actual returned continuation and reads fresh document permission. It preserves the frozen source high-water, never invents a token, and replaces the displayed page with at most50 freshly authorized headers. Earlier pages are not accumulated: retaining them would retain headers whose policy may have changed between requests. Refresh opens a fresh window and exposes newly appended captures. Counts are only records shown; gaps and bounded coverage remain explicit. A cursor discontinuity has unknown cause and is not called data loss. No event bodies or hidden source details are synthesized to fill gaps.

Saved view changes are one actual canonical service command with a durable ID. An unknown acknowledgment retains the exact command/payload for Retry save. An acknowledged save followed by a failed read is labeled saved and requires refresh. A competing canonical revision preserves local settings and requires explicit Use saved view/Keep my view against a fresh document. Current denial clears displayed headers, provenance and source options; local form intent is retained privately until access returns. Inactive views do no new reads/queries, stale reads cannot replace newer state, and disposal prevents late repaint or navigation.

Owned tests use actual TimelineService/Kernel SQLite on the same canonical ingestion schema with explicitly synthetic retained headers and test host policy. The event-publication callback is a test boundary; Root owns its real stream/IPC adapter. Actual service CAS/receipts/filtering/window fences, an existing MotionCoordinator and a finite CPU DOM driver verify behavior. Root's released contract/service dependencies are excluded from this worker commit. These checks do not establish native input, layout, frame rate, graphics recovery, provider execution, native restart or artistic acceptance. Root retains manifest/type promotion, canonical creation, App/Main/IPC mounting and combined native qualification.

The registration tail exposes a reference-only Timeline manifest with a wide rounded default and a separate chronology compact identity. Canonical creation/configuration stays with Root's actual TimelinePort entrypoint. Generic block factories and new-resource template roles cannot create an empty/default time view or silently broaden its scope. Explicit reference templates preserve the same configured Timeline ID/version. The old ten-kind native preparation remains fixed; it does not automatically qualify this new family.

DirectResourcePorts adds `timelines?: { port: TimelinePort; motion: ExperienceMotionPort; viewId: string; resourceTitle?(resourceId: string): string | undefined }`. The direct adapter mounts this same viewer without a NoteSession or placement, forwards frame/reflow/flush and uses its existing canonical `openResource` callback for source navigation. Root should supply a unique presentation viewId and enable the manifest only when the actual mount and attachment ports are connected. Workspace compact projection is `blockIdentity({ kind: 'timeline', resource, timeline: { document, window } })`, fed by the viewer's onProjection callback; absent data remains loading and a denied/null projection remains unavailable.
