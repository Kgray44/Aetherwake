# Native OpenAI provider module

Source-only, native-process integration module. Nothing imports this into the running application yet. Offline RSA and network-double tests establish local validation behavior, **not** successful registration, account eligibility, model entitlement, billing, inference, native secret protection or usable application acceptance.

Aerynth remains proprietary. OpenAI currently documents **personal projects that run locally** separately from open-source projects. This module accepts only an explicit native policy decision `local-personal-project`, scoped to the current owner's local installation. It does not add an open-source license or assert permission for paid, remote or distributed use. Such use needs a fresh eligibility/terms review and any required access. The actual OAuth server and user-granted scopes determine account availability. [Official cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt), [availability](https://developers.openai.com/siwc/quickstart).

## Integration contracts

- `chatgpt-plan-responses`: ordinary Aerynth-managed chats, selected protected ChatGPT registration, verified OIDC identity and **actual returned** direct-use scope. This grants no ChatGPT conversation history, native account memory or synchronization. Models originate from the same selected credential. A model listing is not inference success.
- `openai-api-vela`: Vela's own authorized instructions/context and separately configured API credential, organization/project and API billing. A ChatGPT token cannot satisfy this route. No fallback between routes. Codex is not imported, launched, reconfigured or impersonated.

`SiwcSessionManager` requires injected native OS credential storage, a stable native host-ID store, a real loopback-listener proof and explicit local-registration policy. It does not start a listener/browser, store files or own a conversation/execution database. The native host must keep the authorization URL private: returning sign-in may include `id_token_hint`. Tokens, scopes and identities belong in protected storage, never renderer IPC, logs, analytics, canonical messages or source control. The only public auth result is bodyless `PublicAuthStatus`.

`NativeCredentialVault.withLock` MUST provide **cross-process** exclusion for a registration; an in-process mutex is insufficient. `compareAndSwap` MUST atomically check the existing version and replace the entire registration/token set durably. Errors must leave the previous record intact and must not return secrets. The native integration must stop/review a refresh whose rotated-token persistence fails; this module does not retry a grant or claim recovery of an unknown write. Neither the test-double lock nor in-memory test restart demonstrates OS-vault or multi-process durability.

Sign-in generates fresh state/nonce/S256 PKCE and binds the exact `http://127.0.0.1:<port>/auth/callback` and native listener identity. Native registration policy must run before a new registration. The issued client ID is retained under lock/CAS **before** code exchange; an incomplete record has no identity/token/inference authority. Returning sign-in uses that exact client and host and cannot replace a known issuer/subject/client tuple. JWT signature/issuer/audience/expiry/nonce/authorized-party checks use pinned `jose` and fixed official discovery/JWKS endpoints. No token claims are interpreted as workspace IDs. Auth attempts expire in five minutes and are capped at four per manager. [Registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [accounts and refresh](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [token fields](https://developers.openai.com/siwc/token-sharing-open-source/token-reference).

Refresh is explicit, exact-version and serialized through the injected lock. The newest access token, replacement refresh token, granted scopes and expiry are one CAS write. Terminal refresh rejection clears credential authority while retaining the registration mapping. Invalid successful rotation data also disables the old renewable session. Transient failures retain the current record and require an explicit recovery decision; there is no automatic retry. Sign-out attempts the discovered same-issuer revocation endpoint once, clears credentials locally and reports **unconfirmed** when upstream revocation was not observed. The native host must revalidate session version before every dispatch and invalidate cached catalogs after account/session changes.

`ResponsesTransport` accepts exact typed instructions and bounded explicit message context from the canonical host. Root retains all canonical history, memory provenance, task/execution state, permission/budget grants and persistence. Native `authorize` binds exact emitted JSON SHA-256, bytes, canonical request/execution/configuration/model IDs and context authorization digest. Native `revalidate` must check current permissions, policy, source versions, selected account and catalog boundary after asynchronous reads. `resolveCatalog` is the fresh, authorized catalog for that same selected configuration and credential boundary. The module's transient in-flight set is **not** persistent replay protection: the canonical authorizer must consume grants and enforce execution idempotency.

Fixed public endpoints only: GET `/v1/models`, POST `/v1/responses`; redirects are rejected. Requests explicitly use `stream:true`, `store:false`, an explicit input array and instructions. No agent harness, tool execution, background turn, provider-side conversation, previous response ID, arbitrary parameter passthrough, automatic retry or billing fallback. Local caps default to 256 KiB request/event/output, 2 MiB stream and 90 seconds; native configuration can only reduce them. These byte caps are local resource bounds, not model context-window or spend guarantees; native approval must impose authorized budget policy. [Models and direct inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [supported preview fields](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Completion is reported only for an observed matching `response.completed`. Incomplete, provider failure, EOF/drop/timeout and uncertain post-dispatch cancellation stay distinct. Partial text/refusal is retained; usage comes only from actual provider usage fields. No token counts, pricing, task success, memory access or tool results are invented. Cancellation never claims server confirmation. Canonical event sinks must reject late events after their own execution lease expires. [Streaming](https://developers.openai.com/api/docs/guides/streaming-responses), [stream events](https://developers.openai.com/api/reference/resources/responses/streaming-events), [recovery codes](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

## Source validation

Node >=24.18. Install from this directory with `npm ci --ignore-scripts --no-audit --no-fund --cache .runtime/npm-cache`; run `npm test`. The lockfile pins `jose@6.2.15` to npm registry integrity. Its MIT dependency license does not change the application's proprietary status. [Maintainer](https://github.com/panva/jose), [version metadata](https://registry.npmjs.org/jose/6.2.15).

Remaining native integration: protected cross-process vault/CAS, selected-account configuration and model catalog ownership, user-reviewed loopback/browser consent, canonical chat history and isolated Vela persona/memory context, durable execution/grant/cancellation handling, live provider and restart acceptance, and correct billing/usage disclosures. No live network auth/inference, browser, account probe, user profile access, GUI or secret lookup is part of these tests.
