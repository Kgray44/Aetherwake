## Implementation status and evidence rules

Acceptance of a **design** or **governing requirement** establishes the expected behavior. It does not establish that a feature is implemented, integrated, independently verified, artistically approved or released. The current source baseline includes a functioning API/tool runtime, durable missions, block views, GPU 3D Constellation, and earlier GPU ribbon-based Vela presence. It does **not** establish shipped volumetric Mind, full immersive Stream V2, end-to-end automatic memory extraction/CIE, independent cloud-agent success, or complete multi-display/voice qualification.

Each implementation PR must link the applicable accepted IDs, source-owner interfaces, negative/security cases, exact tested revision, native evidence and remaining gaps. Synthetic fixtures must be labeled. Historical human/provider receipts and sensitive context must remain outside this public repository.

## Required implementation sequence and gates

1. Reconcile authority and implement adapters to existing domain owners, including the Personal Context engine and CIE. Do not invent a parallel memory database.
2. Establish source-linked durable task checkpoint and provider-neutral context manifests with read/write policy gates.
3. Implement optional automatic memory-candidate extraction, provenance/correction and user review; evaluate actual recall and leakage on held-out cases.
4. Demonstrate cross-provider/branch/restart continuity and concurrent-agent conflict resolution using real task identities and unknown-effect safety.
5. Prototype the GPU Nebula with true volume, moving-camera proof, internal flow and canonical event feeds; select techniques by measurements.
6. Integrate the full-screen Stream V2, Activity Theater, Active Projects Dock and continuous spatial transitions with working canonical domain controls.
7. Verify end-to-end task success, privacy, visual/artistic fidelity, GPU resource use, multi-display behavior and resilience under realistic Windows load.
