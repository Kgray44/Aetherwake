## How to read the evidence

| State | Meaning |
| --- | --- |
| Missing | A runtime implementation or product path was not found at this revision. |
| Designed | A governing requirement or design exists for the described scope. |
| Implemented | Code exists. The inventory identifies whether it is wired into the connected application. |
| Synthetically verified | A deterministic fixture, scripted transport or hosted suite exercised the named behavior. |
| Natively verified | A cited run exercised a real desktop, OS or hardware effect within the stated environment. Source-mode, hidden windows and scripted approvals each limit the claim. |
| Provider-qualified | A cited real account/model/transport exercised the named operation. Qualification is scoped to that configuration and observation. |
| Accepted | An authorized reviewer accepted the specific product outcome under Charter 15. Ratified design is recorded in governance. |
| Released | A supported distribution was published with release evidence. A locally packaged review candidate is implementation evidence. |

These labels apply to the described slice. A row may have both an implemented baseline and designed or missing breadth. A test path identifies a relevant witness. A dated run or receipt supplies the result. The [FI acceptance registry](FI-ACCEPTANCE-REGISTRY.json) maps 108 requirement rows to related witnesses and records adjudication separately.

## Product and runtime map

Aetherwake develops Aerynth, a local-first spatial desktop for conversation, project work and verified execution. Vela is the assistant across those surfaces. Ordinary conversation runs on its own path. Missions add explicit scope, plans and verifiable effects. The target spatial experience preserves continuity across projects, workspaces, Vela Presence and the project Intelligence Stream.

`src/` contains a placeholder. Most connected application code currently sits under `prototypes/`. Start at [Aerynth.cmd](../../Aerynth.cmd) → [Electron main](../../prototypes/visual-experience/cinematic-v3/native/desktop-main.cjs) → [preload](../../prototypes/visual-experience/cinematic-v3/native/desktop-preload.cjs) and [renderer application](../../prototypes/visual-experience/cinematic-v3/src/application.ts). Electron hosts sensitive OS and consent operations and uses the [desktop backend host](../../prototypes/integrated-backend/src/desktop-host.mts). [Backend](../../prototypes/integrated-backend/src/service.mts) transports typed commands to a [worker](../../prototypes/integrated-backend/src/worker.mts) running [BackendCore](../../prototypes/integrated-backend/src/core.mts). Shared renderer-facing contracts live in [application-contract](../../prototypes/application-contract/). The preview/recording entry uses [native/main.cjs](../../prototypes/visual-experience/cinematic-v3/native/main.cjs).

Core composes SQLite-backed domain owners. WorkspaceKernel owns resource identity. ConversationGraph owns graph and message lineage. MissionService owns task state. CIE derives scoped context from those owners. AIR/Vela decides or proposes how to respond. Trust checks scope and effect authority at the host and domain boundaries. The Performance Governor admits local resources. AEP projects observed execution. Renderer views consume these projections and invoke typed commands. See [local-first storage](../architecture/AERYNTH-LOCAL-FIRST-STORAGE-AND-CONTINUITY.md) and [A4 handoff](A4-ARCHITECTURE-RECOVERY-HANDOFF.md) for contracts and recovery evidence.

### Known gaps and risks

- **Correctness.** The ordinary chat interruption race in [#65](https://github.com/Kgray44/Aetherwake/pull/65) has a component regression and a pending fix. Partial plans can finish a verified child while the overall objective remains blocked. Preserve unavailable sources and uncertain external effects across restart. The original strict FI-2 retrieval result was 7/8 on a small corpus. Broader evidence selection, contradiction handling and repeated cold/warm tail latency remain unqualified. [Combined receipt](MISSION-01-04-INTEGRATION.md) · [PR #60](https://github.com/Kgray44/Aetherwake/pull/60)
- **Performance.** One mixed ARIE run measured 9.32 s of overlapping remote execution during real GPU contention. That receipt establishes overlap for those two calls. Repeated, comparable verified workloads under idle, balanced and foreground pressure, input/frame/audio timing, attribution overhead and hard-floor recovery remain open. [FI-3 native evidence](FI-3-ARIE-NATIVE-VERIFICATION.md)
- **Security and privacy.** Native review and scoped grants exist. Independently exercise revocation and correction between preview, dispatch, settlement and restore, adversarial document content, changed file identity, cross-account egress, credential custody and backup lifecycle. Profile data has distinct protections from OS-wrapped credentials. [Backend security notes](../../prototypes/integrated-backend/SECURITY.md) · [Trust charter](../../governance/14-TRUST-PRIVACY-AND-AUTONOMY.md)
- **Architecture.** BackendCore and the renderer application assemble many concerns. The cross-workstream integration record owns coordination for shared files. Keep the transaction, source identity, trust and event owners intact when extracting journal/read projections or renderer seams. [A0/A1 owner map](A0-A1-RUNTIME-OWNERSHIP.md)
- **UX.** Real partial outputs, provider denials, stale evidence and permission state need understandable, keyboard-accessible journeys in the shipping shell. Continuity through long sessions, reduced motion, display changes and the owner-directed moving-camera spatial experience needs native evidence. [Quality charter](../../governance/15-QUALITY-VERIFICATION-AND-ACCEPTANCE.md)
