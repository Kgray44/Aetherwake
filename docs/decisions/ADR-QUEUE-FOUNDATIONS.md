## Common experiment and decision packet

Each spike names the owner, candidate versions, target devices/OS, equivalent user scenario, profiling procedure, repeat count, confidence/variance, failure modes, accessibility and privacy implications, migration/rollback path, cost and maintenance burden. Store raw trace and screen/video capture identifiers without private content. Compare cold start, steady state, idle/minimized use, input response, worst-case transition frame times, memory and GPU use where applicable. Record unavailable measurements rather than estimates disguised as observations. A screenshot, one fast machine or synthetic peak FPS cannot establish cinematic quality or product readiness. Stop a spike when a candidate is disqualified by a demonstrated constraint or equivalent tests give enough evidence to decide; if inconclusive, state exactly what is missing. Review accepted ADRs after material provider/platform changes or contrary benchmarks.

## Dependency and freeze order

ADR-001/002 experiments start in M1 but cannot finalize before M2 confirms App Server integration constraints. ADR-004's protocol/auth spike starts early in M2 and informs ADR-006. ADR-003/007 must be resolved together before M3 canonical migrations; ADR-005 follows a working two-window resource fixture. A draft contract can support parallel experiments, but a v1 public interface freeze follows the relevant owner decisions and compatibility tests. A chosen stack remains replaceable behind the [reference architecture](../architecture/REFERENCE-ARCHITECTURE-v0.1.md) and [versioned contracts](../specifications/PROVISIONAL-INTERFACE-CONTRACTS-v0.1.md).

## Open product decisions outside the ADRs

The owner must determine the initial target hardware/support matrix; which ordinary conversational provider path is acceptable; what local and remote history can be imported under actual capabilities; retention/deletion/export defaults; branch-handoff sharing defaults; which external effects require approval; and distribution/signing policy. These are not inferred from technology benchmarks. The current repository contains governance and router code, not running Aerynth product source; therefore every ADR above remains research, not a fait accompli.
